## 1. Формулировка задачи

**Предметная область:** Рынок краткосрочной аренды жилья.

**Цель анализа:** Оценить состояние и структуру рынка краткосрочной аренды в выбранном городе на основе данных Inside Airbnb.

**Основной вопрос:** Какие районы города наиболее привлекательны для краткосрочной аренды с точки зрения плотности предложения, средней цены и уровня спроса?

**Уточняющие вопросы:**
1. Какие типы жилья (весь дом / отдельная комната / общая комната) преобладают в разных районах?
2. Есть ли районы с аномально высокой или низкой средней ценой за ночь?
3. Какая доля рынка принадлежит профессиональным арендодателям (хозяева с 5+ объявлениями)?

**Единица анализа:** Одно объявление (listing) — одна строка в файле `listings.csv`.

**Гранулярность:** Уровень отдельного объявления (снимок на определённую дату).

**Метрики:**
- Цена за ночь (`price`)
- Количество объявлений (`id`)
- Количество отзывов (`number_of_reviews`)
- Доступность в году (`availability_365`)

**Срезы:**
- Район (`neighbourhood`)
- Тип жилья (`room_type`)
- Категория хозяина (по `calculated_host_listings_count`)

## 5. Ограничения и гипотезы

**Ограничения набора:**
1. Это снимок на одну дату, а не временной ряд — динамику не увидеть.
2. Поле `price` указано в валюте платформы и может не отражать реальные цены бронирования.
3. `availability_365 = 0` означает либо «занято», либо «снято с публикации» — точно не различить.
4. Данные могут быть неполными для некоторых районов.

**Гипотезы о качестве данных:**
1. **Г1:** В поле `price` будут выбросы (цены в десятки раз выше среднего).
2. **Г2:** В `reviews_per_month` и `last_review` будут пропуски для объявлений без отзывов.
3. **Г3:** Некоторые хозяева дублируют объявления — это исказит подсчёт рыночной доли.
4. **Г4:** В `neighbourhood` могут быть опечатки или разные варианты написания одного района.
