## 1. Контекст и входные данные

Аналитический вопрос: какие районы Барселоны привлекательнее для краткосрочной аренды с точки зрения количества предложений, средней цены и прокси спроса. Одна строка `listings.csv.gz` соответствует одному объявлению на дату снимка. Основной бизнес-ключ — `id`; повторяющиеся или отсутствующие идентификаторы рассматриваются как критическая проблема.

Входной S3-путь: `s3://raw/inside_airbnb_barcelona/ingested_on=2026-10-30/listings.csv.gz` (проверить совпадение даты с успешным запуском DAG ЛР № 2). Исходный объект в `raw` не изменяется.

## 2. Профиль

Фактические значения необходимо перенести из вывода ноутбука после выполнения всех ячеек:

| Показатель | Фактическое значение |
|---|---:|
| Строк / полей | перенести из фактического вывода |
| Строк с отсутствующей ценой | перенести из фактического вывода |
| Строк без района | перенести из фактического вывода |
| Строк без координат | перенести из фактического вывода |
| Строк, входящих в группы повторяющихся `id` | перенести из фактического вывода |

В ноутбуке дополнительно выводятся схема выбранных полей, распределение по типам жилья и диапазон дат отзывов. Интерпретация наблюдений: пропуски района ограничивают сравнение районов; аномальные или отсутствующие цены могут смещать сравнение стоимости. Конкретные выводы необходимо уточнить по фактическому профилю после запуска.

## 3. Правила качества и результаты

Все пороги заданы как **0 нарушений** и реально сравниваются с результатами проверок. Доля нарушений считается от числа проверенных строк.

| Правило | Проверяемое условие | Критичность / действие |
|---|---|---|
| `unique_listing_id` | `id` отсутствует или повторяется после первого вхождения | critical / quarantine |
| `price_nonnegative` | цена отсутствует, не преобразуется в число или меньше нуля | critical / quarantine |
| `neighbourhood_present` | район отсутствует или пуст | warning / flag |
| `room_type_allowed` | тип жилья отсутствует или вне допустимого справочника | critical / quarantine |
| `coordinates_in_range` | координаты отсутствуют или выходят за допустимые географические диапазоны | warning / flag |
| `reviews_nonnegative` | число отзывов отсутствует или отрицательно | warning / flag |
| `availability_in_range` | доступность отсутствует или не находится в диапазоне 0–365 | warning / flag |

Полная сводка числа проверенных строк, нарушений, долей, порогов и действий формируется в `rules_df` в ноутбуке. После выполнения ноутбука перенести фактические значения в итоговую таблицу:

| ID | Проверено | Нарушений | Доля | Порог | Порог превышен? | Действие |
|---|---:|---:|---:|---:|---|---|
| `unique_listing_id` | заполнить | заполнить | заполнить | 0 | заполнить | quarantine |
| `price_nonnegative` | заполнить | заполнить | заполнить | 0 | заполнить | quarantine |
| `neighbourhood_present` | заполнить | заполнить | заполнить | 0 | заполнить | flag |
| `room_type_allowed` | заполнить | заполнить | заполнить | 0 | заполнить | quarantine |
| `coordinates_in_range` | заполнить | заполнить | заполнить | 0 | заполнить | flag |
| `reviews_nonnegative` | заполнить | заполнить | заполнить | 0 | заполнить | flag |
| `availability_in_range` | заполнить | заполнить | заполнить | 0 | заполнить | flag |

Критические нарушения исключаются из `staging` и сохраняются в карантине с исходными полями, `quality_rule_ids` и `quarantine_reason`. Нарушения с действием `flag` остаются в `staging` с явными булевыми признаками `quality_flag_*`. Несколько причин карантина перечисляются через запятую в `quality_rule_ids`, а пояснения — через `; ` в `quarantine_reason`.

## 4. Подготовленные данные

Пути результатов:

- `s3://staging/inside-airbnb-barcelona/source_ingested_on=<та же дата>/staging.parquet`
- `s3://staging/inside-airbnb-barcelona/source_ingested_on=<та же дата>/quarantine.parquet`

Ноутбук повторно читает оба объекта из S3 и проверяет баланс `raw = staging + quarantine`, а также отсутствие нарушений критических правил в `staging`.

Количество строк после первого запуска: `raw = ...`, `staging = ...`, `quarantine = ...` (перенести из вывода ноутбука). После повторного запуска с теми же входом и параметрами: `staging = ...`, `quarantine = ...` (сравнить результаты двух запусков).

Нормализация добавляет числовые представления `price_normalized`, `latitude_normalized`, `longitude_normalized`; исходные поля при этом сохраняются. Добавляются признаки качества района, координат, отзывов и доступности. Бизнес-агрегации не выполняются.

## 5. Воспроизводимость и ограничения

Ноутбук: `notebooks/profile_quality.ipynb`. Для воспроизведения нужны доступный raw-объект в SeaweedFS, корректные переменные S3-подключения и полный `RAW_S3_PATH` с тем же `ingested_on`. Следует перезапустить ядро и выполнить все ячейки сверху вниз дважды; числа строк должны совпасть.

Ограничения: `listings.csv.gz` представляет снимок рынка, а не историю фактических бронирований; количество отзывов является лишь приближённым показателем спроса. Отсутствие доступности не позволяет однозначно отличить занятость жилья от снятия объявления с публикации.
